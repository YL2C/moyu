# 墨游个人版与同步

上游：[lishbuwe/moyu](https://github.com/lishbuwe/moyu)。个人仓库：[YL2C/moyu](https://github.com/YL2C/moyu)。

`main` 保留上游原版，`codex/personal` 是日常使用与发布的个人版。GitHub Pages 应部署 `codex/personal` 的根目录。

## 个人习惯

- 输入：括号内写描述、动作、心理或剧情推动，括号外直接写台词；无需引号。游玩页有插入括号按钮。导入旧故事时不改写存档里的原文，发给模型时会附上当前输入约定。
- 选项：A/B/C/D 四项；点击只在输入框填写字母，可继续补充。发送时按当前章节展开完整选项（作为括号内的行动），再附上补充文字；手动输入 AB 等多选同样展开。删除字母后不再带上旧选项。
- 输入栏：括号按钮在游玩输入框内右侧；游玩与讨论的灰色提示统一为较小的「自由输入…」，实际输入文字仍为 16px。
- 更新：设置底部和游玩页右上角菜单均有「检查更新并刷新」。生成中或输入框有未发送内容时会先提示处理，避免刷新打断；只更新网页文件，不清除故事、密钥或数据库。离线资源安装绕过 HTTP 旧缓存，在线请求会重新核验版本。
- 弹幕：输入框上方随时开关，对当前故事生效并保存。关闭会隐藏已有弹幕，之后生成也不要求弹幕；不删除已经生成的内容。
- 固定姓名与开场示例已换成通用提示。世界设定、角色和规则模块依然按故事配置。
- 本机数据库和当前故事标记使用 `moyu-yl2c-personal` 命名，缓存只管理个人版的条目。旧版故事需先导出备份，再到个人版导入；API 密钥、转发口令需另外填写。
- 新故事默认规则从资料库《世界书 V4.4.4》（2026-11-08）第一至八部分提炼：主动主持、重大选择权、生成性人设、自然节点、选择状态、小说表达、信息边界、连续性与最小纠错。未复制具体人物示例、专题扩展、附录或完整原文；后续修改集中在 `js/personal.js` 的 `PERSONAL_RULES`。已经导入或保存的故事规则不会被自动覆盖。

## 以后怎么同步

给 Codex 的一句话：

> 同步 lishbuwe/moyu 最新功能到 YL2C/moyu 的 codex/personal，保留个人输入、ABCD、弹幕开关、独立存储和个人世界书；先检查本地改动，合并并验证后发布。

执行者先读本文件。不要用整文件覆盖或 `reset --hard` 同步个人分支。`main` 可通过 GitHub 的 Sync fork 更新；这只更新原版镜像，不会更新个人应用。个人应用需要把上游提交合并到 `codex/personal`：

```sh
git switch codex/personal
git status --short
git fetch upstream main
git merge upstream/main
```

如果尚未设置上游，先添加 `upstream`，地址为 `https://github.com/lishbuwe/moyu.git`。遇到冲突保留新功能与个人行为，尤其注意 `js/personal.js` 的调用、`js/prompt.js`、`js/views/play.js`、数据库名及 `sw.js`。发布前更新应用版本和缓存版本，执行 `npm ci` 与 `npm test`，并验证浏览器验收页。`tests/preview.html` 使用内存数据，不访问或改写真实故事。最后推送 `codex/personal`，等待 Pages 部署成功。

共同需要的修复可以另开分支贡献给原版；个人文风和世界书留在个人分支或本机配置中。两人的故事、密钥和使用偏好不会随代码合并同步。

## 服务器转发

个人站点来源为 `https://yl2c.github.io`。2026-11-13 已在现有香港转发器的 `.env` 中加入此来源，验证个人版与原版来源都返回 200，缺少口令返回 401，未允许来源返回 403。手机端仍需在设置中填写原 HTTPS 地址与独立口令，再在模型连接里启用“经服务器转发”；口令不可写入仓库。

现有服务器的 Compose 项目名是 `moyu-relay`，目录是 `/opt/moyu-relay/server`。维护时必须指定项目名，例如 `docker compose -p moyu-relay ps`；不能在该目录直接用默认项目名重建，否则会另建容器并争用 8787 端口。重建现有转发容器会清空其临时生成缓存，应在合适时机执行。原服务与个人版共用同一个转发器，不会因此同步各自的本机故事。


## 0.6.15-personal.1

- 多选选项用 A+B 显示，保持点选顺序，可取消单项并保留补充文字。发送时展开全部原文。
- 设置按栏目折叠并记忆状态；预设按组显示，Markdown导入保留文件分组，散模块可归组，批量删除可撤销。故事开关只影响当前故事。

- 讨论附件支持原始PNG/JSON/TXT/MD。本地解析后勾选文字进入讨论，原始字节保留在讨论及其备份，不压缩、不转码，不向模型发送图片。附带正则与脚本只展示和保存，不执行。
- 主角初始资料与当前状态分开，依据当前分支原文生成更新建议，审阅后保存，可撤销；正文、讨论与番外只读取该分支及时间点有效的状态。
- 生成正文可少量使用 **加粗** 与 ==强调色==；页面只创建文字节点，阅读设置可关闭，不额外调用API。
